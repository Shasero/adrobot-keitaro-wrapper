# Правила работы с AdRobot

- Владелец проекта принимает решения и даёт разрешения. Архитектор определяет требования и проверяет качество. Codex выполняет согласованные задачи в их границах.
- Перед изменениями проверь состояние репозитория и прочитай применимую документацию. Сверяй API-контракты с источниками и явно отмечай пробелы. Расширение задачи согласуй с владельцем.
- Обязательны FastAPI и SQLAlchemy 2.x. Согласованный стек включает Python 3.12, SQLite, Alembic, HTTPX, Pydantic Settings, Pytest и HTML/CSS/Vanilla JS. Для новых фреймворков и инфраструктуры нужны обоснование и согласование.
- Храни секреты на сервере в переменных окружения или локальном `.env`. В `.env.example` используй безопасные заглушки. Исключай секреты из логов, ответов фронтенду, тестовых данных, Git diff, отчётов и документации. Не сохраняй реальные ответы API с токенами, реальные офферные URL и диагностические выгрузки.
- В автоматических тестах используй HTTP-моки. После приёмки техническим архитектором разрешены обычный локальный commit и push принятых изменений в `develop`. Приёмку проводит архитектор. Merge, push в `main`, force push, разрушительные команды Git, удаление данных, развёртывание и реальные изменяющие запросы Keitaro требуют отдельного разрешения владельца.
- Изменяй только кампании текущего тестового проекта. Перед записью проверь настроенный префикс имени кампании и принадлежность потока этой кампании. Глобальный каталог офферов, домены, группы и источники доступны приложению для чтения. Это правило проекта для общего стенда. Соответствующее ограничение на стороне API не подтверждено.
- При редактировании офферов отправляй полный целевой список привязок и сохраняй остальные поля потока. Перед публикацией проверь актуальность состояния, после записи перечитай поток и проверь сохранённые поля. Одного успешного HTTP-ответа для подтверждения недостаточно.
- Разделяй API-клиент, бизнес-логику, валидацию и доступ к БД. Избегай лишних абстракций. Источник актуальной опубликованной конфигурации — Keitaro.
- Проверяй изменения тестами. В отчёте указывай точные команды, фактические результаты, ограничения и оставшиеся риски. Пиши отчёты на русском, используй английские идентификаторы Python и API.
