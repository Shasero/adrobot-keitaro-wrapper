# Контракт Keitaro Admin API для AdRobot

Контракт фиксирует результаты ручных экспериментов владельца проекта на тестовом эмуляторе 24–25 ноября 2026 года. В TASK-002 Codex перенёс эти наблюдения в документацию. Примеры составлены с условными идентификаторами. Опубликованная схема в отдельных деталях расходится с наблюдениями на эмуляторе. [Официальная документация Keitaro Admin API](https://admin-api.docs.keitaro.io/)

## Авторизация и настройки

- Базовый путь — `/admin_api/v1`. Базовый URL и ключ берутся из окружения. Заголовки `Api-Key: <secret>` и `Accept: application/json` используются для запросов API, `Content-Type: application/json` — для POST и PUT.
- ID домена, группы кампаний и источника трафика задаются конфигурацией и проверяются по справочникам. Владелец подтвердил для тестового стенда домен 1813, группу 10332 и источник 836. Эти значения относятся к конкретному окружению. Публичный код использует параметры конфигурации.
- Префикс имени кампании также задаётся конфигурацией. Перед изменением проверяются префикс и принадлежность потока кампании текущего тестового проекта.

## Проверенные маршруты

Все пути указаны относительно `/admin_api/v1`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/domains` | Список доменов |
| GET | `/groups?type=campaigns` | Группы кампаний |
| GET | `/traffic_sources` | Источники трафика |
| GET | `/offers` | JSON-массив офферов, на стенде наблюдалось 170 записей |
| GET | `/offers/{id}` | Один оффер |
| GET | `/campaigns` | Список кампаний без параметров |
| POST | `/campaigns` | Создание кампании |
| GET | `/campaigns/{id}` | Проверка сохранённой кампании |
| GET | `/campaigns/{id}/streams` | JSON-массив потоков кампании |
| POST | `/streams` | Создание потока |
| GET | `/streams/{id}` | Проверка потока |
| PUT | `/streams/{id}` | Изменение потока |

## Создание кампании

Проверенная структура тела POST `/campaigns` с условными ID.

```json
{
  "name": "test_example_campaign",
  "alias": "test-example-campaign",
  "type": "position",
  "state": "active",
  "domain_id": 101,
  "group_id": "102",
  "traffic_source_id": 103
}
```

В запросе `group_id` передавался строкой, сервер вернул число. Подтверждено сохранение домена, группы, источника и ротации по позиции. Наблюдались серверные значения по умолчанию `uniqueness_method=ip`, `cookies_ttl=24`, `cost_type=CPC`, `cost_value=0`, `cost_currency=USD`, `cost_auto=false`.

В примере интерфейса ТЗ включён флаг стоимости из параметра `cost`. Эксперимент с настройками по умолчанию вернул `cost_auto=false`. Необходимость явного `cost_auto` предстоит определить. Перед добавлением `uniqueness_method` в POST требуется отдельная проверка. Поле `token` ответа чувствительно. Его значение исключается из публичного кода, документации и логов.

## Обычный поток с GEO и переходом на Google

Проверенная структура тела POST `/streams` для выключенного диагностического потока.

```json
{
  "campaign_id": 123,
  "name": "Flow 1",
  "type": "regular",
  "schema": "redirect",
  "action_type": "http",
  "action_payload": "https://www.google.com",
  "state": "disabled",
  "collect_clicks": true,
  "filter_or": false,
  "filters": [
    {"name": "country", "mode": "accept", "payload": ["US"]}
  ]
}
```

POST и повторный GET подтвердили поля. Эмулятор принял `action_payload`. В опубликованной схеме запроса `StreamObject` это поле отсутствует. Для фильтра проверен массив строковых кодов страны с `US`. Пустой `payload` оставляет корректность GEO неподтверждённой. Во вручную созданном включённом эталоне обычный поток имел `position=1`.

## Замыкающий поток с оффером

Проверенная структура тела POST `/streams` для выключенного потока.

```json
{
  "campaign_id": 123,
  "name": "Flow 2",
  "type": "default",
  "schema": "landings",
  "action_type": "http",
  "state": "disabled",
  "collect_clicks": true,
  "filter_or": false,
  "offers": [
    {"offer_id": 501, "share": 100, "state": "active"}
  ]
}
```

POST и повторный GET подтвердили привязку оффера с долей 100%. В ответе наблюдались `action_payload=null`, `offer_selection=before_click`, `filters=[]` и `landings=[]`. Во вручную созданном включённом эталоне замыкающий поток имел `position=2`. В опыте с программным созданием сервер назначал позиции по порядку создания. Явная передача `position` ещё требует проверки.

В конечной кампании оба потока должны иметь состояние `active` и сохранять порядок обычного и замыкающего потоков. POST активных потоков и полный программный сценарий остаются непроверенными. Эксперименты подтвердили сохранение настроек. Фактические HTTP-переходы предстоит проверить отдельно.

## Изменение привязок офферов

Проверенная структура тела PUT `/streams/{id}` с условными ID.

```json
{
  "offers": [
    {"offer_id": 501, "share": 70, "state": "active"},
    {"offer_id": 502, "share": 30, "state": "active"}
  ]
}
```

- На выключенном потоке `landings` исходная привязка сохранила свой ID, её доля изменилась со 100 до 70, новая привязка получила 30. Повторный GET подтвердил обе активные привязки, сумму 100 и сохранение остальных полей после PUT только с `offers`.
- На выключенном диагностическом потоке `redirect` проверены добавление одной привязки с долей 100 и удаление всех привязок телом `{"offers": []}`. URL перехода, фильтр и состояние потока сохранились.
- При публикации формировать полный целевой массив привязок с `offer_id`, `share` и `state`. Серверные поля `id`, `stream_id`, `created_at` и `updated_at` из ответа исключать из запроса. Сверять состояние перед PUT и проверять поля повторным GET. DELETE `/offers/{id}` исключён из сценария редактирования потока.
- Требуют отдельной проверки непустая замена с исключением одной из нескольких привязок, удаление всех привязок в `landings`, отправка привязки в состоянии `disabled` и поведение при конкурентных изменениях.

## Особенности эмулятора

| Наблюдение | Вывод для приложения |
| --- | --- |
| GET `/stream_filters`, `/stream_schemas`, `/stream_types`, `/streams_actions` вернули HTTP 404. | Основной сценарий обходится без этих маршрутов. |
| GET `/streams/search?query=test` вернул HTTP 422. Эмулятор интерпретировал `search` как целочисленный `stream_id`. | Использовать список потоков кампании. |
| GET `/campaigns?limit=100` вернул HTTP 422. Точная причина неизвестна. GET без параметров сработал. | Использовать подтверждённый запрос без параметров. |
| `/offers/search` отсутствует в имеющейся OpenAPI-спецификации. | Искать по полученному каталогу на стороне приложения. |
| В PowerShell некоторые способы оборачивания результатов исказили количество элементов. HTTP-ответы в проверенных случаях содержали корректные JSON-массивы кампаний, потоков и офферов. | В Python разбирать JSON штатно. |

## Дальнейшая проверка

В отдельной задаче проверить фактические HTTP-переходы, программное создание двух активных потоков, частичный сбой создания, конкурентные изменения и удаление одной из нескольких привязок. Закрепление долей, их распределение и синхронизация черновиков относятся к логике AdRobot и требуют тестов приложения.
